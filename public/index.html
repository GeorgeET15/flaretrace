How Clara Works

  1. Report the problem

    Describe symptoms or paste output from ping, traceroute, nslookup, or ipconfig. Clara starts building an incident model immediately.

    $ describe the problem or paste command output…
  2. Evidence reconciles

    Each message updates the incident state. Contradictions are resolved, tests are deduped by type and target, and the hypothesis list is replaced in full each turn.

    connectivity → testsPerformed → hypotheses → nextStep
  3. State survives sessions

    Each browser session maps to a dedicated Durable Object with its own SQLite database. Close and reopen the browser and your incident is waiting exactly where you left it.

    getAgentByName(sessionUUID)

The incident model

Clara doesn’t just generate text. It maintains structured incident state that the Inspector panel exposes in real time.

Connectivity fields are updated only when explicit evidence exists in the current message. Fields with no new evidence are preserved from prior turns.

The hypothesis list is replaced in full each turn. No stale hypotheses survive new evidence. 

messages
  full conversation history

connectivity
  gateway    { address?, status }
  internetIp { address?, status }
  dns        { status }

testsPerformed
  latest result per type+target
  { type, target?, result, summary }

hypotheses
  current plausible causes, replaced each turn

nextStep
  single most useful next action
